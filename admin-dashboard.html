Penjelasan Arsitektur Sistem: Apakah Kasir Memerlukan Pemanggilan API Lain?

Dalam arsitektur faskes modern (Klinik / Rumah Sakit Jiwa), modul kasir ini dirancang untuk dapat dihubungkan ke 4 jenis API eksternal sesuai kebutuhan integrasi:

1. Payment Gateway API (Inbound/Outbound Webhook) Untuk pembayaran non-tunai (QRIS Dinamis, Kartu Debit, Virtual Account Bank) via provider seperti Midtrans, Xendit, atau DOKU. Saat pasien scan QRIS dan sukses membayar di HP-nya, webhook callback otomatis mengubah status antrean menjadi Lunas (QRIS) tanpa kasir perlu mengetik manual.
2. BPJS Kesehatan VClaim / PCare Bridging API Bila faskes menerima pasien BPJS, kasir memerlukan pemanggilan API VClaim untuk verifikasi hak kepesertaan, pembuatan nomor SEP (Surat Eligibilitas Peserta), dan pengajuan klaim tarif INA-CBGs.
3. SIMRS & Jurnal Akuntansi Keuangan (ERP) Mengirimkan rekap penerimaan kas harian ke software akuntansi rumah sakit (SAP, Odoo, atau SIMRS lokal) agar buku kas besar ter-update secara otomatis di akhir shift kerja kasir.
4. SATUSEHAT Billing & E-Kwitansi (Kemenkes) Standardisasi FHIR resource Coverage dan Claim yang menghubungkan riwayat Encounter pasien dengan tagihan resmi faskes.
